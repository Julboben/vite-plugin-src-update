# vite-plugin-src-update

[![npm](https://img.shields.io/npm/v/vite-plugin-src-update)](https://www.npmjs.com/package/vite-plugin-src-update)
[![CI](https://github.com/Julboben/vite-plugin-src-update/actions/workflows/ci.yml/badge.svg)](https://github.com/Julboben/vite-plugin-src-update/actions/workflows/ci.yml)

Use Vite when something else renders your HTML. This plugin writes the right `<script>` and `<link>` tags into a template file for Shopify, BigCommerce Stencil, ASP.NET MVC / Web Forms, Twig or any other backend:

- **`vite` (dev):** tags pointing at the dev server, including the HMR client.
- **`vite build`:** tags for the hashed build output, with each platform's own URL helper if you want one.

The backend doesn't need to read a manifest or know anything about Vite.

Supports Vite 5, 6, 7 and 8, on Node.js `^20.19.0 || >=22.12.0`.

## Install

```sh
npm install vite-plugin-src-update --save-dev
```

## Quick start

```ts
// vite.config.ts
import { defineConfig } from "vite";
import vitePluginSrcUpdate from "vite-plugin-src-update";

export default defineConfig({
  build: { outDir: "dist" },
  plugins: [
    vitePluginSrcUpdate({
      templateFilePath: "templates/partials/vite-assets.html",
      input: ["src/main.js", "src/styles/print.css"],
    }),
  ],
});
```

The plugin also uses `input` as Vite's build input, so you don't need `build.rollupOptions.input`. An `input` can be a folder: `input: ["src/entrypoints"]` makes every script and style file inside it an entry.

Then include `templates/partials/vite-assets.html` from your layout. While `vite` is running it contains:

```html
<!-- IMPORTANT: This file is automatically generated by vite-plugin-src-update.
Do not modify it directly, as any changes will be overwritten by the next build. -->
<script type="module" src="http://localhost:5173/@vite/client"></script>
<script type="module" src="http://localhost:5173/src/main.js"></script>
<script type="module" src="http://localhost:5173/src/styles/print.css"></script>
```

After `vite build` it contains:

```html
<!-- IMPORTANT: … -->
<link rel="stylesheet" href="/dist/assets/main-DXYuBBGC.css">
<link rel="stylesheet" href="/dist/assets/print-Bk3Lm9Qa.css">
<link rel="modulepreload" href="/dist/assets/vendor-C1a2b3c4.js">
<script type="module" src="/dist/assets/main-8WQytZJj.js"></script>
```

The file is only rewritten when its content changes, so file watchers (Stencil CLI, Shopify CLI, `dotnet watch`) don't reload for nothing.

## Platform recipes

### BigCommerce Stencil

```ts
export default defineConfig({
  build: { outDir: "assets/dist" },
  plugins: [
    vitePluginSrcUpdate({
      templateFilePath: "templates/components/common/vite-assets.html",
      input: ["assets/js/app.js"],
      platform: "bigcommerce",
    }),
  ],
});
```

```html
<!-- generated -->
<script type="module" src="{{cdn '/assets/dist/assets/app-8WQytZJj.js'}}"></script>
```

Include it with `{{> components/common/vite-assets}}` in `templates/layout/base.html`.

### Shopify

```ts
export default defineConfig({
  build: {
    outDir: "assets",
    emptyOutDir: false, // keep the theme's other assets
  },
  plugins: [
    vitePluginSrcUpdate({
      templateFilePath: "snippets/vite-assets.liquid",
      input: ["frontend/entrypoints"],
      platform: "shopify",
      // Optional: Shopify's theme hot reload, as vite-plugin-shopify adds it.
      devTags: [
        `<script type="module" id="hot-reload-client" src="https://cdn.jsdelivr.net/npm/@shopify/theme-hot-reload/dist/theme-hot-reload.min.js"></script>`,
      ],
    }),
  ],
});
```

The `shopify` platform sets the Vite options Shopify needs (see [Platform defaults](#platform-defaults)), so there's no `base` or `assetsDir` to configure.

```liquid
{% comment %} generated {% endcomment %}
<script type="module" src="{{ 'main-8WQytZJj.js' | asset_url | split: '?' | first }}"></script>
```

Include it with `{% render 'vite-assets' %}` in `layout/theme.liquid`.

### ASP.NET MVC (Razor)

```ts
export default defineConfig({
  build: { outDir: "Content/dist" },
  plugins: [
    vitePluginSrcUpdate({
      templateFilePath: "Views/Shared/_ViteAssets.cshtml",
      input: ["Scripts/src/main.ts"],
      platform: "razor",
    }),
  ],
});
```

```cshtml
@* generated *@
<script type="module" src="@Url.Content("~/Content/dist/assets/main-8WQytZJj.js")"></script>
```

Include it with `@Html.Partial("_ViteAssets")` in `_Layout.cshtml`. In dev, `@` in dev-server URLs is written as `@@`, so Razor doesn't treat `/@vite/client` as code.

### ASP.NET Web Forms

Put markers straight into `Site.Master` (see [Updating part of a file](#updating-part-of-a-file)):

```aspx
<head runat="server">
  <%-- vite-plugin-src-update:start --%>
  <%-- vite-plugin-src-update:end --%>
</head>
```

```ts
vitePluginSrcUpdate({ templateFilePath: "Site.Master", input: ["src/main.ts"], platform: "webforms" });
// writes: <script type="module" src="<%= ResolveUrl("~/dist/assets/main-8WQytZJj.js") %>"></script>
```

Alternatively, write to an include file (`templateFilePath: "ViteAssets.inc"`) and add `<!-- #include file="ViteAssets.inc" -->` to the master page.

### Other template languages

Header comments are formatted for `.html`, `.htm`, `.php`, `.liquid`, `.hbs`, `.handlebars`, `.mustache`, `.cshtml`, `.vbhtml`, `.razor`, `.aspx`, `.ascx`, `.master`, `.twig`, `.njk`, `.jinja`, `.j2`, `.ejs` and `.erb`. Any other extension gets an HTML comment. Add your own with `commentTemplates`, and wrap URLs any way you need with an `assetUrl` function:

```ts
vitePluginSrcUpdate({
  templateFilePath: "templates/vite.tpl",
  commentTemplates: { ".tpl": (comment) => `{* ${comment} *}` },
  assetUrl: (url) => `{$smarty.const.CDN_URL}${url}`,
});
```

## Updating part of a file

By default the plugin owns the whole template file. To put the tags inside an existing file (a layout or master page), add two marker lines, in any comment syntax:

```html
<head>
  <title>My shop</title>
  <!-- vite-plugin-src-update:start -->
  <!-- vite-plugin-src-update:end -->
</head>
```

Only the lines between the markers are replaced, using the start marker's indentation. Use the `marker` option to update several places in one file, e.g. styles in `<head>` and scripts before `</body>`:

```ts
vitePluginSrcUpdate([
  { templateFilePath: "layout/theme.liquid", input: ["src/theme.css"], marker: "vite-styles" },
  { templateFilePath: "layout/theme.liquid", input: ["src/theme.js"], marker: "vite-scripts" },
]);
```

To prevent accidents, the plugin refuses to overwrite an existing file that has no markers and wasn't generated by it. Set `force: true` to allow that.

## Options

Pass one options object, or an array of them to update several templates from one build.

**Essentials**

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `templateFilePath` | `string` | **required** | Template file to update, relative to the current working directory. |
| `input` | `string[]` | build input | Entries for this template, relative to the Vite root. A folder includes every script and style file inside it. Builds include these entries plus their CSS and shared chunks. If Vite has no build input configured, all templates' inputs become the build input. |
| `platform` | `"bigcommerce" \| "shopify" \| "razor" \| "webforms"` | – | Wraps built asset URLs in the platform's helper and sets [platform defaults](#platform-defaults). |

**Built asset URLs**

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `base` | `string` | see below | Public URL prefix for built assets, e.g. `/dist/` or `https://cdn.example.com/`. |
| `assetUrl` | `(url, fileName) => string` | – | Custom URL wrapper; takes precedence over the `platform` helper. |

**Generated tags**

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `attributes` | `Record<string, string \| boolean>` | `{}` | Extra attributes on every tag, inserted verbatim, e.g. `{ nonce: "{{ nonce }}" }`. |
| `integrity` | `boolean` | `false` | Adds `integrity="sha384-…"` and `crossorigin` to built tags. |
| `modulePreload` | `boolean` | `true` | Adds `<link rel="modulepreload">` for chunks the entries import. Off when `build.modulePreload` is `false`. |
| `injectClient` | `boolean` | `true` | Injects Vite's HMR client (`@vite/client`) in dev. |
| `devTags` | `string[] \| (origin) => string[]` | `[]` | Extra tags written after the HMR client in dev only, inserted verbatim. |

**Template file**

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `marker` | `string` | `"vite-plugin-src-update"` | Marker name for [partial updates](#updating-part-of-a-file). |
| `force` | `boolean` | `false` | Overwrite a file this plugin didn't generate. |
| `commentTemplates` | `Record<string, (comment) => string>` | built-in | Header comment formatters per extension, merged with the defaults. |

**Debugging**

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `dryRun` | `boolean` | `false` | Log the output instead of writing it. |
| `verbose` | `boolean` | `false` | Log every template update. |

Unknown options are reported as warnings, so typos don't go unnoticed.

**Deprecated** (still work, with a warning)

| Option | Use instead |
| --- | --- |
| `assetUrl: "<platform>"` | `platform: "<platform>"` |
| `cdn: true` | `platform: "bigcommerce"` |
| `outDir` | `base` (`outDir` keeps 1.x's paths without a leading slash) |

**Default `base`:** your Vite `base` if you set it to an absolute path or URL. Otherwise the plugin uses `/<build.outDir relative to the root>/`, e.g. `/dist/`. If `build.outDir` is outside the Vite root, the URL can't be inferred; set `base` (you'll get a warning).


### Platform defaults

The `bigcommerce` and `shopify` platforms fill in Vite options they need. They only apply when you haven't set the option yourself:

| Platform | Vite option | Default | Why |
| --- | --- | --- | --- |
| `bigcommerce`, `shopify` | `base` | `"./"` | Chunks, fonts and images are loaded relative to the file that references them, so they come from the CDN instead of the store's domain. |
| `shopify` | `build.assetsDir` | `""` | Shopify's `assets` folder is flat. |
| `shopify` | `server.cors` | `localhost`, `127.0.0.1` and `https://*.myshopify.com` | Theme previews on `myshopify.com` can load scripts from the dev server. |

## Tips

### Dev server URL, Docker and HTTPS

The dev tags use Vite's [`server.origin`](https://vite.dev/config/server-options#server-origin) when it's set. If you don't set it, the plugin sets it to the dev server's address, so fonts and images referenced from CSS also load from the dev server rather than the backend. Set it whenever the browser reaches Vite on a different address than the one Vite listens on, e.g. in Docker, DDEV or behind a proxy. It's also required in middleware mode.

Without it, the plugin uses the configured `server.host` name, or `localhost`. When the backend is served over HTTPS (IIS Express, BigCommerce), run Vite over HTTPS too, e.g. with [`@vitejs/plugin-basic-ssl`](https://github.com/vitejs/vite-plugin-basic-ssl) or mkcert. Otherwise the browser blocks the dev scripts as mixed content.

### Testing on other devices (tunnel)

To try dev mode on a phone or share it with a colleague, expose the dev server through a tunnel, e.g. a free [Cloudflare quick tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/):

```sh
cloudflared tunnel --url http://localhost:5173   # prints https://<random>.trycloudflare.com
```

Then point Vite at the tunnel. The plugin writes the tunnel URL into the template, and the HMR client connects through it too:

```ts
const tunnel = process.env.TUNNEL_URL; // e.g. https://random-words.trycloudflare.com

export default defineConfig({
  server: {
    origin: tunnel,
    allowedHosts: tunnel ? [new URL(tunnel).hostname] : [],
  },
  // …
});
```

```sh
TUNNEL_URL=https://random-words.trycloudflare.com npx vite
```

If you've configured `server.hmr`, point it at the tunnel as well: `hmr: { host: new URL(tunnel).hostname, protocol: "wss", clientPort: 443 }`. Quick tunnels get a new URL every time they start, and the template keeps the tunnel URL until the next dev or build run.

### CORS

Vite's dev server only allows cross-origin requests from `localhost`/`127.0.0.1` pages by default (the `shopify` platform also allows `*.myshopify.com`). If your backend runs on another host name (e.g. `https://shop.local`), add it to [`server.cors`](https://vite.dev/config/server-options#server-cors):

```ts
server: { cors: { origin: "https://shop.local" } }
```

### Module preload polyfill

As [Vite's backend integration guide](https://vite.dev/guide/backend-integration) recommends, add this at the top of your entry to polyfill `modulepreload` in older browsers:

```js
import "vite/modulepreload-polyfill";
```

### React

`@vitejs/plugin-react` needs its Fast Refresh preamble on pages Vite doesn't serve. Import it at the top of your client entry:

```js
import "@vitejs/plugin-react/preamble";
```

### Legacy browsers

With [`@vitejs/plugin-legacy`](https://github.com/vitejs/vite/tree/main/packages/plugin-legacy), the template also gets `nomodule` scripts for the legacy polyfills and entries. The fallback Vite adds to its own HTML for browsers that support ES modules but not modern syntax isn't included. If you need it, copy it from your Vite-built `index.html`.

### Full-reload plugins

If a plugin such as [`vite-plugin-full-reload`](https://github.com/ElMassimo/vite-plugin-full-reload) watches your template folder, it also sees the template this plugin writes when the dev server starts, and reloads the page once for nothing. Exclude the generated file from its globs:

```ts
fullReload(["theme/**/*.liquid", "!theme/snippets/vite-tag.liquid"]);
```

### Don't ship dev URLs

After `vite` (dev) stops, the template still points at the dev server until the next `vite build`. Always build before deploying.

If the template is a dedicated generated file, gitignore it and let your build or deploy pipeline create it. If it lives in a committed layout (markers), commit the build output, not the dev output.

## Coming from vite-plugin-shopify

Replace `shopify({ … })` with:

```ts
vitePluginSrcUpdate({
  templateFilePath: "snippets/vite-tag.liquid",
  input: ["frontend/entrypoints/theme.ts"], // what the layout renders
  platform: "shopify",
  devTags: [/* theme hot reload, see the Shopify recipe */],
});
```

- Set `build.outDir` (e.g. `"assets"`), and add `build.rollupOptions.input` with all entries if some are built but not rendered through the snippet.
- `vite-plugin-shopify` decides per `render 'vite-tag', entry: '…'` call which entry to load. This plugin writes a fixed list of tags per file, so use one template per combination of entries. Existing `render 'vite-tag' with 'theme.ts'` calls keep working, because the parameter is ignored.
- Delete the old generated `snippets/vite-tag.liquid` once. The plugin won't overwrite a file another tool generated.
- Its `~/` and `@/` import aliases aren't added; define them in `resolve.alias` if your code uses them.

## Migrating from 1.x

See the [2.0.0 changelog](./CHANGELOG.md#200) for breaking changes and migration steps. In short:

- Built URLs now start with `/`.
- `input` now filters build output per template.
- Hand-written files are no longer overwritten without markers or `force`.
- `outDir` is now `base`, and `cdn: true` is now `platform: "bigcommerce"`.

## Roadmap

Ideas that may be added later; open an issue if you need one of them:

- **Stylesheet tags for CSS entries in dev.** CSS entries are loaded with `<script type="module">` in dev, so their styles appear only after JavaScript runs (a brief flash of unstyled content). Writing `<link rel="stylesheet">` for them instead would avoid that. CSS imported from a JavaScript entry isn't affected.
- **One template per entry.** A `[name]` placeholder in `templateFilePath` (e.g. `snippets/vite-[name].liquid`) to write a separate template for each entry, so pages can load only what they need.
- **Stylesheet preloading for Shopify.** An option to use `stylesheet_tag: preload: true`, which makes Shopify send an early preload hint for render-blocking CSS. Only worth adding if testing shows a real gain in Largest Contentful Paint.
