# Changelog

All notable changes to this project are documented here. Add notes under `## Unreleased` as you
work; the release workflow turns that section into the new version and uses it as the GitHub release notes.

## Unreleased

## 2.1.3

### Added

- Shopify theme previews on custom and market domains can load dev server assets. With `platform: "shopify"`, the dev server checks a domain's public `/meta.json` once, and allows it if it's a Shopify storefront. No list of domains to maintain, and other websites stay blocked.
- When Shopify CLI's `SHOPIFY_FLAG_STORE` environment variable is set, only that store's domains are allowed.

## 2.1.2

### Fixed

- Fonts and images referenced from CSS (and other imported assets) now load from the dev server in dev mode. Without `server.origin`, Vite made their URLs root-relative, so pages served by the backend (e.g. Shopify CLI on `127.0.0.1:9292`) requested them from the wrong host and got 404s. The plugin now sets `server.origin` to the dev server's address when you haven't set it.

### Documentation

- README tip for testing dev mode on other devices through a tunnel (e.g. Cloudflare quick tunnels).
- README tip for excluding the generated template from full-reload plugins, and a Roadmap section with ideas for later.

## 2.1.1

### Fixed

- `platform: "shopify"` now strips the `?v=` query that Shopify's `asset_url` adds. Chunks import each other by plain file name, so `modulepreload` links with the query pointed at a different URL and made the browser download those chunks twice.

## 2.1.0

### Added

- `platform` option (`"bigcommerce"`, `"shopify"`, `"razor"`, `"webforms"`) for the URL helper and platform defaults. `assetUrl` is now only for custom functions, and can be combined with `platform`.
- Warnings for unknown options, so typos like `templatePath` don't go unnoticed.
- `input` accepts folders: every script and style file inside becomes an entry.
- When Vite has no build input configured, the templates' inputs become the build input, so `build.rollupOptions.input` is optional.
- Platform defaults for Vite options you haven't set. `"bigcommerce"` and `"shopify"` set `base: "./"`, so chunks, fonts and images load from the CDN. `"shopify"` also sets `build.assetsDir: ""` and allows `https://*.myshopify.com` in `server.cors`.
- `devTags` option for extra dev-only tags, e.g. Shopify's theme hot reload.
- README section on switching from `vite-plugin-shopify`, and options grouped by purpose.

### Changed

- With the `"bigcommerce"` or `"shopify"` platform and no `base` set, Vite now builds with `base: "./"` instead of `"/"`. Before, dynamically imported chunks and CSS `url()`s pointed at the store's own domain instead of the CDN. Set `base` to keep the old behaviour.

### Deprecated

- `assetUrl: "<platform>"`: use `platform: "<platform>"`. `cdn: true` (use `platform: "bigcommerce"`) now warns too, like `outDir`.

## 2.0.0

### Breaking changes

- **Built asset URLs are root-relative by default.** 1.x wrote `vite-build/main.js`, which browsers resolve against the current page (`/products/shoe/vite-build/main.js`). 2.0 writes `/vite-build/main.js`, or uses Vite's `base` when you set it. Use the new `base` option to control the prefix.
- **`input` now filters build output.** Each template only gets the entries listed in its `input` (plus their CSS and shared chunks). 1.x wrote every entry and stylesheet into every template.
- **Stylesheets come first**, followed by `modulepreload` links and then scripts.
- **The template file is protected.** An existing file that wasn't generated by this plugin and has no markers is no longer overwritten. Add markers, or set `force: true`.
- **New header comment wording.** Handlebars uses `{{!-- --}}`, and Razor keeps line breaks. Unknown extensions now get an HTML comment instead of plain text that showed up on the page.
- **Write failures fail the build** instead of only logging an error.
- `commentTemplates` now extends the defaults instead of replacing them.

### Added

- `base` option for the public URL prefix of built assets.
- `assetUrl` presets: `"bigcommerce"`, `"shopify"`, `"razor"`, `"webforms"`, or a custom function.
- Marker-based updates: only the lines between `<marker>:start` and `<marker>:end` are replaced, so tags can live inside an existing layout. Several markers per file are supported (`marker` option).
- `attributes` option (e.g. a CSP `nonce`), `integrity` option (SRI hashes) and `modulePreload` option.
- `<link rel="modulepreload">` for shared chunks.
- `@vitejs/plugin-legacy` support (`nomodule` polyfills and SystemJS entries).
- Default comment formats for `.htm`, `.php`, `.handlebars`, `.mustache`, `.vbhtml`, `.razor`, `.aspx`, `.ascx`, `.master`, `.twig`, `.njk`, `.jinja`, `.j2`, `.ejs` and `.erb`.
- Missing template directories are created.
- Windows (CRLF) line endings in existing templates are preserved.
- Named export `vitePluginSrcUpdate` and exported `DEFAULT_COMMENT_TEMPLATES`.

### Fixed

- Builds with several outputs (e.g. `@vitejs/plugin-legacy`) no longer overwrite the template with only the last output.
- SSR builds and non-client environments no longer overwrite the template.
- The dev server uses `server.origin` when set, the configured `server.host` name, and brackets IPv6 addresses.
- Middleware mode writes the template when `server.origin` is set, and warns otherwise.
- Razor templates escape `@` (as in `/@vite/client`) as `@@`.
- Dev inputs outside the Vite root are served through `/@fs/`.
- `dryRun` prints its output without needing `verbose`.
- Logging goes through Vite's logger, so it respects `logLevel`.
- Option descriptions are kept in the published type definitions.

### Deprecated

- `outDir`: use `base`. It still works and keeps the 1.x behaviour.
- `cdn: true`: use `assetUrl: "bigcommerce"`.

### Migrating from 1.x

1. If you set `outDir`, rename it to `base`. To keep 1.x's paths exactly (no leading slash, e.g. for `{{cdn 'assets/dist/…'}}`), use `base: "assets/dist/"`.
2. Replace `cdn: true` with `assetUrl: "bigcommerce"`.
3. With several templates, check that each one's `input` lists everything it should load.
4. Rebuild once and review the diff of your generated templates.
